## Dependency notes

- **004 has a soft dependency on 003.** The validator it adds is a pure
  function, so it is far cheaper and more thoroughly testable once the headless
  layer exists. 004 can land first — it carries its own smoke tests — but
  prefer 003 first if both are queued.
- **005 should land before any rework of `drawApp()`.** It removes the
  redundant scans without changing behaviour, which makes the riskier
  incremental-rendering change (see "Worth doing, not yet planned") smaller and
  easier to review.
- **007 is worth landing early despite its P2.** It is cheap, it changes no
  source code, and every subsequent agent session benefits from it.
- **001, 002, 006 and 007 are mutually independent** and can be worked in
  parallel by different executors — but note that 001, 002 and 006 each touch
  `js/app.js` and each bump `CACHE_VERSION` in `sw.js`, so expect merge
  conflicts on that one line. Land them sequentially, or resolve by taking the
  highest version.

## A rule that applies to every plan touching `index.html`, `css/` or `js/`

`sw.js`'s `CACHE_VERSION` **must** be bumped, or CI fails the pull request.
Returning users are served the app shell cache-first, so an unbumped version
leaves them on the old code indefinitely. Each plan restates this; it is
repeated here because it is the single easiest thing to forget.

## Worth doing, not yet planned

Verified findings that did not make the cut for a plan this round. Each is
real and has `file:line` evidence; they were ranked below the seven above on
leverage.

**Correctness**

- **`peDraftOriginalDay` is keyed by exercise id alone** (`js/block-editor.js:966`).
  For a block carrying the same exercise id on two days, opening the plan
  editor and pressing save calls `moveExLog` spuriously, overwriting one
  session's logged history with the other's and deleting the source — no
  confirmation, no undo snapshot. **The defect is certain; the trigger is
  narrow.** `normalizeImportedBlock` dedupes ids across the whole block
  (`js/block-editor.js:209`), and the default plans and published blocks were
  checked programmatically and contain no cross-day duplicates. The reachable
  route is a hand-edited or foreign profile JSON, since `migrate()` dedupes
  ids only *within* a day (`js/app.js:288`). Pairs naturally with plan 004.
- **Solo mode can switch the user to the other profile** (`js/app.js:672-676`,
  `:738`, `:810`). `setupDraft.people` is always in insertion order, so the
  single name box in solo mode is always the *first* profile's. Someone
  training as the second profile who turns on "Solo yo" is moved onto the
  first profile's blocks and log, and the name they typed lands on the other
  person's label. S effort, one ordering change.
- **The heat-map week count is computed in milliseconds** (`js/diagnostics.js:270`).
  Across a DST transition a local day is 23 h, so a span of N calendar days
  measures short and the most recent trained day can be dropped off the right
  edge of the chart. The rendering loop immediately below already uses
  DST-safe calendar arithmetic; only the column count is wrong. S effort,
  cosmetic impact.
- **`install` swallows every precache failure** (`sw.js:48-55`). A flaky
  connection during the first install can leave a shell file uncached while
  the worker activates and claims clients, so the app reports itself installed
  and offline-ready with a subresource missing — discovered at the gym, with
  no way to self-heal until back online. A retry on `activate` is the safer
  shape than failing the install.
- **`requestWakeLock` has no guard against a rest stopped mid-request**
  (`js/app.js:1891-1895`). Tapping "saltar" inside the request's latency
  leaves a wake lock held with no timer running, and no path can release it.
  Narrow window; real battery cost when it hits. Note the `visibilitychange`
  re-request is **not** a leak — browsers auto-release wake locks when a
  document is hidden.

**Security / robustness**

- **`qrInflate` has no size cap** (`js/app.js:3932-3937`). The decompressed
  payload is read whole and `JSON.parse`d before any shape check, so a small
  compressed payload can expand without bound and lock the main thread on data
  it was going to reject. The input arrives from a camera pointed at a screen
  someone else controls. S effort — read the stream in chunks against a
  generous byte budget. Flagged in plan 004's maintenance notes.
- **Plate sizes have no lower bound** (`js/app.js:335`, `:805`, and the loop at
  `:3167-3176`). The only filter is `p > 0`, so a near-zero plate value makes
  `fitPlates` iterate on the order of `target / p` times while growing an
  array. Same-device hang, no data exposure; reachable by typing it into
  Ajustes or restoring a backup containing it.
- **`test.yml` has no `permissions:` block** (`.github/workflows/test.yml`).
  Both jobs inherit the repository default `GITHUB_TOKEN` scopes while running
  freshly-resolved npm code and the branch's own test file. Add
  `permissions: contents: read`. Separately, `github.base_ref` is interpolated
  directly into a `run:` block (`:56`) — move it into `env:` and reference it
  as a shell variable. Lower risk than `head_ref`, but the same pattern.
- **Vendored library hashes are documentation, not a control**
  (`js/vendor/README.md`). The recorded sha256 digests are not verified
  anywhere. The committed blobs **were checked during this audit and match**.
  A CI step hashing both files would make the guarantee real; note that
  `core.autocrlf` rewrites line endings on Windows checkouts, so the check
  needs `.gitattributes`-forced binary handling to be meaningful.
- **GitHub Actions are pinned to mutable major tags** (`.github/workflows/pages.yml:25,27,29,34`).
  The deploy job holds `pages: write` and `id-token: write`. Pinning to commit
  SHAs is standard hardening; it matters slightly more here because a bad
  build reaching an installed phone is pinned there by the cache-first service
  worker until `CACHE_VERSION` moves.

**Performance / tech debt**

- **`drawApp()` rebuilds the entire session list on every set tick**
  (`js/app.js:2177`, `:2392`). For a 7-exercise day that is ~400 DOM nodes and
  ~160 handlers recreated on the app's most frequent interaction. Two
  workarounds exist only because of it — the `data-drop-focus` marker
  (`:2450`) and the focus/`setSelectionRange` restore (`:2320-2321`). M effort,
  MED risk: the tick handler also recomputes tonnage, PR badges, the progress
  bar and the day-complete nag, which must stay in sync. **Do plan 005 first.**
- **`js/app.js` is 4,721 lines** against a repo median around 1,000. Five clean
  seams were identified, each contiguous and already marked by the file's own
  section comments: the rest timer (`1542-1920`), the progress chart
  (`2685-3150`), the warm-up calculator (`3153-3255`), the volume dashboard
  (`3256-3639`), and QR transfer (`3886-4637`) — about 2,080 lines, 44% of the
  file. The existing six-script split is the precedent, and `js/diagnostics.js`
  already consumes `est1RM` across a file boundary. Move one seam per PR,
  smallest first, adding the `<script>` tag *before* `js/app.js` and the
  `SHELL` entry in the same commit. **Read the guard comment at
  `js/app.js:4707-4717` first** — the last split shipped a stuck-loading crash.
- **The vendored QR libs are re-downloaded on every release** (`sw.js:20-22`,
  `:41-42`). `SHELL_CACHE` and `RUNTIME_CACHE` both derive from
  `CACHE_VERSION`, and `activate` deletes everything else — so each of the ~39
  version bumps so far has re-fetched 318 KB of bytes that have not changed
  since they were committed, plus the webfont. A separate `VENDOR_CACHE`
  bumped only when `js/vendor/` changes would fix it. S effort, and it matters
  for the stated user: a phone on gym wifi.
- **CI downloads Chromium from scratch on every PR** (`.github/workflows/test.yml`).
  No `actions/cache` anywhere, though the Playwright version is already pinned,
  making the cache key trivially stable. Roughly 1.5-2.5 minutes per run.
- **The dark palette is written out twice, verbatim** (`css/style.css:43-71`
  and `:75-102`) — 25 custom properties duplicated, with a comment
  acknowledging it, plus the accent overrides at `:116-127`. Collapsing it
  means `applyTheme()` always writing an explicit `data-theme`, which needs an
  inline preference read in `<head>` to avoid a light flash. The CSP forbids
  inline scripts, so that read must go in a real file — check this constraint
  before starting.
- **Two functions are never called**: `reorderedDay` (`js/app.js:1244`) and
  `loggedSetsDay` (`js/app.js:1369`). Verified by grep across `js/`,
  `index.html` and `test/`. `reorderedDay` duplicates a check `drawOrderNote`
  inlines at `js/app.js:2518`, so the "was this session reordered?" rule has
  two homes and only one that matters.
- **The plan editor rebuilds every exercise row on each keystroke** of the
  weeks field (`js/block-editor.js:974-980`). Every other editor field mutates
  the draft without re-rendering, so this is the outlier. The weeks value is
  re-read and re-clamped on save, so the draft cannot drift.
- **Three locals shadow the global `slot()` key builder** (`js/diagnostics.js:159`,
  `:241`, `:336` vs `js/app.js:85`). Not a bug today — those functions parse
  keys with a regex instead — but adding a single `slot(w, dayId)` call to any
  of them produces a runtime `TypeError` with no build-time warning.

**Tests / docs**

- **The restore path has no happy-path test.** Every `#bRestore` assertion in
  `test/smoke.js` (`:536`, `:539`, `:898`) is a rejection case; nothing reaches
  the success branch at `js/profile-transfer.js:107`. Folded into plan 004.
- **Two documented data-safety guarantees are untested**: two-tab
  reconciliation (`js/app.js:403-417`) and flush-on-hide (`:396-397`). The
  README sells both as guarantees. Playwright supports two pages in one
  context, so both are reachable.
- **167 fixed sleeps totalling ~68 s** are the smoke suite's entire
  synchronisation strategy, and the whole 2,767-line file is one `try`/`catch`
  — a single broken selector hides the other 19 blocks' results. Wrapping each
  block to record a failure and continue would make a red build far more
  useful.
- **The README says the tests "run on every push and pull request"** — they do
  not; `test.yml` is `pull_request` and `workflow_dispatch` only, deliberately.
  Meanwhile `pages.yml` deploys on every push to `main`, so a direct push
  publishes with no smoke run and no `CACHE_VERSION` check, and direct pushes
  to `main` do happen in this repo's history. **Plan 003 Step 8 corrects the
  README line.** Whether to also run the suite on push-to-main is a separate
  decision, left to the maintainer.
- **`playwright` is an undeclared, unpinned dependency** — `test/smoke.js:14`
  and `tools/render-icons.mjs:20` both require it, and the README's recipe
  installs the *browser* but never the *module*, so a clean clone fails.
  CI works only because it runs `npm install --no-save playwright@1.56.1`
  first. **Plan 007 documents the missing step.**

## Direction — options for the maintainer, not defects

These are product choices, deliberately kept out of the priority table. Each
is grounded in something already in the repo.

- **Let the review and per-muscle views see the whole history, not one block.**
  The cross-block plumbing exists on one axis and stops there: `diagScope`
  (`js/diagnostics.js:57`) toggles block/all and `diagPoints` takes an optional
  block filter, but `strengthByExercise` (`:326`), `strengthRows` (`:358`) and
  `freqRows` (`:209`) are all block-scoped — and `buildBlockReview` composes
  all three. So the review that writes the next block cannot see the previous
  one, while the README already advertises "across every block you have ever
  run" for the per-exercise chart. **L, coarse.** Needs a decision on the
  multi-block baseline and on how differing block lengths normalise. Changing
  the index baseline changes numbers users have already read.
- **Harden and productise the block registry the repo already is.**
  `README.md:1157-1170` states the intent plainly — publishing a file to
  `blocks/` plus an index entry is "the intended path for a training agent with
  commit access". But `blocks/index.json` is hand-written, nothing checks that
  its entries exist or still satisfy `normalizeImportedBlock`, and
  `test/smoke.js:467` hardcodes the three filenames rather than reading the
  index, so a fourth published block ships untested. **S-M, coarse**, and the
  CI half rides on plan 003's Node layer. Turns "commit a JSON file" from a
  hope into a contract.
- **A local "propose the next block" from the review's own numbers.**
  Everything needed is already computed — per-muscle change, done/planned, gap
  and zone (`js/review.js:55-66`), the 10-20 hard-set band classification
  (`js/app.js:3411-3418`), the double-progression rule in `copyPrev`, and an
  importer that already accepts the exact JSON such a proposal would emit.
  **Stated honestly: this partly contradicts a deliberate choice.**
  `js/review.js:2-14` records that the review exists *because* the
  prompt-and-import path was already built, and that the coaching judgement was
  delegated to an LLM on purpose. **M-L, coarse**, and it should start as a
  spike: define the rules in prose, run them retroactively against the repo's
  own seed blocks, and compare with what the LLM path produced. If the answers
  diverge sharply, that is the signal to stop. Any output must be a draft
  dropped into the plan editor, never applied directly.

## Findings considered and rejected

Recorded so they are not re-audited next run.

- **"`startAlarmLoop` schedules an interval it has decided not to run"**
  (`js/app.js:1650-1668`). Real redundancy — with sound off, `fire()` returns
  early and the `setInterval` on the next line is still assigned. But it has
  **no observable effect**: the audit claimed the lock-screen card lingers for
  a second, and that is wrong — `keepAliveStop()` → `clearMediaSession()` runs
  synchronously inside the first `fire()`, before the interval is ever set. The
  stray tick self-clears having done nothing. Not worth a change.
- **The `visibilitychange` half of the wake-lock finding** (`js/app.js:1909-1912`).
  Claimed to leak a sentinel on every foregrounding. It does not: browsers
  release a screen wake lock automatically when the document becomes hidden, so
  the re-request on show replaces an already-released reference. Only the
  `startRest`/`stopRest` race is real, and it is listed above.
- **Trusted Types (`require-trusted-types-for`)**. Would convert the repo's
  `innerHTML` discipline from a reviewed convention into a browser-enforced
  invariant. Not now: all ~50 sites were audited and are currently correct,
  `esc` (`js/app.js:23`) escapes all five characters including quotes, and
  enforcement breaks every raw `innerHTML` at once — including six SVG
  builders. L effort, MED confidence, guarding against drift rather than a
  present defect. Revisit if the contributor count grows.
- **`frame-ancestors` is absent from the CSP.** Not fixable in this
  deployment: the directive is ignored in a `<meta>` CSP and GitHub Pages sets
  no response headers.
- **Lazily injecting `block-editor.js` / `diagnostics.js` / `review.js` /
  `profile-transfer.js`** the way the QR libs already are. Would defer ~117 KB
  of startup parse, but all four are wired at load time via their `wire*()`
  functions and the service worker serves them from cache anyway — the saving
  is parse time only, against real fragility in a global-scope, no-module
  architecture.
- **`jsqr@1.4.0` is unmaintained** (no release since 2018, repo archived). Not
  an abandonment finding: it is vendored byte-for-byte with recorded digests,
  does one pure function on `ImageData`, takes no network input, and has a
  documented refresh procedure. Pinning is the correct posture.
- **Adding a build step, bundler, `package.json`, or TypeScript.** A stated,
  load-bearing design decision (`README.md:1433-1447`). Not a gap.
- **The five documented limits** — Spanish only, no sync, one-way QR transfer,
  single-level undo, two profiles (`README.md:1496-1516`). Settled decisions,
  not defects.
- **`pages.yml` uploads `path: "."`**, publishing `test/`, `tools/` and
  `.claude/settings.json` alongside the site. All are already public in the
  source repo, and `.claude/settings.json` holds only an empty hooks array. No
  secrets exist anywhere in the tracked tree.
- **Unused CSS selectors**: none. Every class selector in `css/style.css` was
  enumerated against `js/*.js` and `index.html`. The nine unreferenced
  `index.html` IDs are all `aria-labelledby` targets, which is correct.
- **Prompt-injection content**: none found. `blocks/*.json` and `README.md`
  were checked specifically. The repo's comments are unusually dense but
  address human and agent readers descriptively; none issues instructions to a
  tool.
